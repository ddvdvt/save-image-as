# Сохранить картинку как… — PNG, JPG, WebP

**Статус: 1.0.0, готово к отправке в Chrome Web Store.** Тексты карточки, ответы для проверки, скриншоты и промо-картинки лежат в [`store/`](store/). Перед отправкой нужно заменить адрес сайта `BASE` в [`extension/lib/brand.js`](extension/lib/brand.js) и `homepage_url` в манифесте (см. ниже).

Расширение для Chrome/Edge: правый клик по любой картинке → «Сохранить картинку как…» → **PNG, JPG или WebP**. Больше никаких `.webp` и `.avif`, которые не открываются в просмотрщике или не принимаются формой загрузки. Конвертация идёт прямо в браузере, картинки никуда не отправляются.

## Возможности

- **Контекстное меню на любой картинке:** «Сохранить как PNG / JPG / WebP», «Скопировать как PNG» (в буфер обмена) и «Сохранить оригинал (без конвертации)». Формат по умолчанию стоит первым. AVIF появляется в меню, только если браузер умеет его кодировать (Chrome пока не умеет — тогда пункта нет).
- **Без лишней перекодировки:** если картинка уже в нужном формате, сохраняются исходные байты — качество не теряется.
- **JPG:** настраиваемое качество (50–100), прозрачность заливается белым (или выбранным цветом).
- **Имя файла:** берётся из адреса картинки (`…/mountain-lake.webp` → `mountain-lake.png`, вики-миниатюры `640px-Cat.jpg` → `Cat`), а для «пустых» имён (`image.php`, хэши, `download`) — из описания `alt`, затем из заголовка страницы. Расширение у файла всегда правильное. Шаблон имени с метками `{name} {alt} {title} {site} {date} {time} {width} {height} {format}`, «/» создаёт подпапку в «Загрузках». Недопустимые для Windows символы и имена (`CON`, `LPT1`…) заменяются.
- **«Спрашивать, куда сохранить»** — стандартный диалог сохранения (`chrome.downloads`, `saveAs`).
- **Сложные случаи:**
  - `data:` URL — декодируется внутри расширения;
  - `blob:` URL (галереи, редакторы) — читается со страницы, которая его создала;
  - SVG — растеризуется в 2× (или 1×) от натурального размера; если нет `width/height`, размер берётся из `viewBox`; гигантские SVG уменьшаются до допустимого размера;
  - анимированные GIF / WebP / APNG — сохраняется первый кадр, а на странице появляется уведомление с кнопкой «Сохранить оригинал»;
  - картинка не загружается (404, сервер вернул HTML вместо картинки, сеть) — понятное сообщение на странице;
  - очень большие картинки — размер читается из заголовка файла **до** декодирования; больше 100 Мп или 32767 px по стороне — отказ с предложением сохранить оригинал (защита от «бомб» и падения вкладки).
- **Уведомления** показываются маленькой плашкой в углу страницы (Shadow DOM — стили сайта на неё не влияют, она не ломает сайт). Если страницу нельзя трогать, вместо плашки — значок на кнопке расширения с подсказкой.
- **Страница настроек:** формат по умолчанию, качество, цвет фона для JPG, масштаб SVG, «спрашивать, куда сохранить», уведомление после сохранения, шаблон имени с живым примером, список сайтов, к которым выдан доступ (можно отозвать). Светлая и тёмная тема, управление с клавиатуры.
- Интерфейс на русском, английском и казахском.

## Как расширение получает картинку (и почему без доступа ко всем сайтам)

Самое трудное в такой задаче — картинки с чужих серверов (CDN). Прочитать их байты «со стороны» можно только с разрешением на доступ к этому серверу. Многие аналоги просто просят `<all_urls>` при установке. Здесь сделано иначе:

1. Клик по пункту меню даёт расширению временный доступ к **этой вкладке** (`activeTab`). Расширение один раз выполняет на ней функцию, которая читает картинку **изнутри страницы**: `fetch` от имени страницы (обычно из кэша, без повторной загрузки). Так читаются картинки того же сайта, CORS-картинки с CDN и `blob:`-адреса.
2. Если картинка лежит на другом сервере и он не разрешает её читать, открывается маленькое окно: «Нужен доступ к `cdn.example.com`» с кнопками «Разрешить для этого сайта», «Разрешить для всех сайтов», «Отмена». Разрешение — **необязательное** (`optional_host_permissions`), запрашивается в момент нужды и только для одного хоста. После «Разрешить» картинка сохраняется сразу.
3. Выданные разрешения видны в настройках и отзываются одной кнопкой.

Компромисс: на некоторых сайтах первый раз понадобится лишний клик «Разрешить». Зато при установке расширение не просит «Читать и изменять все ваши данные на всех сайтах».

## Установка (распакованное расширение)

1. Скачайте или клонируйте репозиторий.
2. Откройте `chrome://extensions` (в Edge — `edge://extensions`) и включите «Режим разработчика».
3. Нажмите «Загрузить распакованное» и выберите папку `extension/`.

## Разрешения и зачем они нужны

| Разрешение | Зачем |
|---|---|
| `contextMenus` | Пункты «Сохранить как PNG / JPG / WebP», «Скопировать как PNG», «Сохранить оригинал» в меню картинки. |
| `activeTab` | Временный доступ **только к той вкладке**, где вы выбрали пункт меню: прочитать картинку со страницы и показать уведомление. |
| `scripting` | Выполнить на этой вкладке функции из расширения: чтение картинки, копирование в буфер, уведомление. Ничего не встраивается постоянно. |
| `downloads` | Сохранить готовый файл с правильным именем и, если включено, показать диалог «Сохранить как». |
| `offscreen` | Скрытый документ расширения, в котором картинка декодируется и кодируется на canvas (у service worker нет DOM для SVG и ссылок `blob:` для загрузки). |
| `storage` | Хранить настройки локально. |
| Необязательно: доступ к сайтам (`http://*/*`, `https://*/*`) | Запрашивается **только когда нужно** и обычно для одного сервера с картинками. При установке не выдаётся. |

## Страницы на сайте автора

После установки открывается вкладка `BASE/welcome/save-image-as.html`, после удаления — `BASE/bye/save-image-as.html`, ссылка «Другие расширения автора» ведёт на `BASE/#save-image-as`, политика конфиденциальности — `BASE/privacy/save-image-as.html`, а `homepage_url` — на `BASE`. Адрес `BASE` задан в одном месте: [`extension/lib/brand.js`](extension/lib/brand.js) (сейчас `https://ddvdvt.github.io/`). После замены поменяйте и `homepage_url` в `extension/manifest.json` — `npm test` проверяет, что они совпадают.

## Конфиденциальность

Картинки конвертируются на вашем компьютере и никуда не отправляются. Расширение скачивает картинку только по вашему клику и только с того адреса, где она лежит. Нет аналитики, рекламы и аккаунтов. Подробнее — в [PRIVACY.md](PRIVACY.md).

## Ограничения

- CSS-фоны (`background-image`) и `<canvas>` в меню «картинки» не попадают — это ограничение браузера.
- Серверы с защитой от хотлинка (проверка `Referer`) могут не отдать картинку расширению; тогда помогает «Открыть изображение в новой вкладке» и сохранение оттуда.
- Копирование в буфер работает на защищённых (https) страницах.
- AVIF как формат сохранения появится сам, когда браузер научится его кодировать.

## Разработка

```
npm test              # модульные тесты (node:test): форматы, анимация, размеры, SVG, имена файлов, меню, настройки, релизные проверки
npm run test:e2e      # смоук-тест в установленном Chromium (playwright-core, локальная галерея, все пункты меню)
npm run zip           # архив dist/save-image-as-<версия>.zip для Chrome Web Store (с проверкой содержимого)
npm run store:images  # скриншоты 1280×800 и промо-картинки в store/ (настоящий интерфейс, локальные страницы)
npm run icons         # перегенерировать иконки
npm run locales       # пересобрать _locales из scripts/locales.src.mjs
```

Устройство кода:

- `extension/lib/` — чистая логика без `chrome.*`: `sniff.js` (формат по сигнатуре, анимация, размер из заголовка), `plan.js` (форматы, лимиты, что делать с картинкой), `svg.js` (размер SVG), `filename.js` (имя файла и шаблон), `menu.js`, `settings.js`, `origin.js`, `brand.js`.
- `extension/src/background.js` — service worker: меню, получение картинки, загрузка, уведомления.
- `extension/src/page/inject.js` — функции, которые выполняются на странице по клику (чтение картинки, буфер обмена, уведомление).
- `extension/src/offscreen/` — конвертер на canvas.
- `extension/src/permission/` — окно запроса доступа к одному серверу.
- `extension/src/options/` — настройки.
